## 1. Scaffolding commands

Versions are whatever the registries return *today* (see scaffold.md step 2). Pin the Python version you chose:

```bash
mkdir backend && cd backend
uv init --app --no-workspace --python <researched-python> --name <project>-backend
rm -f main.py hello.py            # uv init sample file, if created
uv add "django[argon2]" "psycopg[binary]" gunicorn "procrastinate[django]" django-stubs-ext
                                   # supervisord is installed in the image, not here
uv add django-ninja                # Ninja variant
# or: uv add djangorestframework drf-spectacular   # DRF variant
uv add --dev pytest pytest-django pytest-cov pytest-xdist factory-boy ruff mypy django-stubs deptry import-linter complexipy pytest-randomly
# DRF variant also: uv add --dev djangorestframework-stubs
uv run django-admin startproject config .
mkdir -p apps && touch apps/__init__.py
```

Then copy the skill's `assets/backend/` into it (adds `config/env.py`, `apps/core` with base models, UUID check, `jobs.defer`, job tasks, backups and commands, `apps/accounts`; nothing generated by Django is overwritten), patch `config/settings.py` and `config/urls.py` and add `config/settings_test.py` as described in `settings.md`, and create `config/api.py` from section 5 or 6.

## 2. Directory layout

```
backend/
├── manage.py
├── pyproject.toml, uv.lock
├── config/                 project package
│   ├── settings.py         generated by startproject, patched per settings.md
│   ├── settings_test.py    tests: dev settings + fast password hasher (settings.md 4b)
│   ├── env.py              env helpers (bool/list/int, APP_URLS parsing, SECRET_KEY guard)
│   ├── api.py              API root: mounts routers, exposes urlpatterns for /api/
│   ├── urls.py             /api/ + /django-admin/ (signs in through the app's login)
│   ├── asgi.py, wsgi.py
├── locale/de/LC_MESSAGES/  django.po (committed; .mo built in Docker and CI)
├── scripts/                check_licenses.py, check_openapi.py, check_translations.py (run by `just check-backend`)
└── apps/
    ├── core/               base models, system checks, health endpoint, jobs.py (defer), tasks.py,
    │                       services/backups.py, commands (ensure_admin, set_password, backup_database)
    ├── accounts/           custom User, auth API
    └── <feature>/
        ├── apps.py         name="apps.<feature>", label="<feature>"
        ├── models/         __init__.py re-exports; a file per model with the helpers only it uses
        ├── admin/          __init__.py imports each module; a file per model's admin
        ├── api/            Ninja routers or DRF views/viewsets, one file per resource
        ├── schemas/        Ninja Schemas   (DRF: serializers/), one file per resource
        ├── services/       business rules: writes, permissions, workflows; defers jobs (core.jobs.defer) for side effects
        ├── selectors/      read/query logic reused by several endpoints (optional)
        ├── migrations/
        └── tests/          test_<topic>.py files, factories in tests/factories.py if needed
```

Why packages: models, admin, API and tests grow independently; a file per resource keeps diffs and reviews small and lets the `__init__.py` serve as the public surface of the app. Split by cohesion, not by count: two small models that only make sense together share a file; a file is split when it holds two unrelated things, never because it got long. Don't create empty packages "just in case" beyond `models/`, `admin/`, `api/`, `schemas|serializers/`, `tests/` — add `services/`/`selectors/` when there is something to put in them.

Each `__init__.py` re-exports explicitly:

```python
# apps/projects/models/__init__.py
from .project import Project
from .task import Task

__all__ = ["Project", "Task"]
```

Relations between files use string references (`models.ForeignKey("projects.Project", ...)`) to avoid import cycles.

## 3. Settings and env

Follow `settings.md`: it lists exactly which parts of the generated `settings.py` / `urls.py` to replace and why. In short: `.env` loading, `APP_URLS`-derived hosts/CSRF/secure cookies, the SECRET_KEY guard, PostgreSQL with `DB_HOST` / SQLite natively, the job queue (PostgreSQL only) and backup settings, `TIME_ZONE`, `LOG_LEVEL`, `DATA_DIR`, the admin under `/django-admin` signing in through the app's login, `STATIC_URL = "/django-static/"`. When you add a setting later, read it through `config/env.py` and document it in `.env.example`.

## 4. Models: packages and UUIDs

- Inherit from `apps.core.models.TimeStampedModel` (UUID pk + created/updated) or `UUIDModel`. Never rely on `DEFAULT_AUTO_FIELD` for our models — it can't be a UUID. The system check `core.E001` fails `manage.py check` if a model in `apps.*` has a non-UUID pk.
- `accounts.User` exists before the first `migrate`. Swapping the user model later is painful, which is why it's created even if nothing customizes it yet. Usernames are case-insensitive: a unique constraint on `Lower("username")` and a manager whose `get_by_natural_key` uses `__iexact`, so login, admin and the commands agree with the constraint (an exact `username=` lookup next to that constraint is the classic bug: `ADMIN_USERNAME=Admin` with an existing `admin` → IntegrityError on every start).
- M2M through tables Django creates implicitly get integer pks; when the relation carries meaning, use an explicit `through` model inheriting `UUIDModel`.
- Order lists explicitly (`Meta.ordering` or in queries) — UUIDv7 sorts by creation time, UUIDv4 does not.
- Invariants as database constraints (`UniqueConstraint`, `CheckConstraint` in `Meta.constraints`) with a validation message in the service; choices as `TextChoices`; every relation with `related_name`.
- No business logic in signals or `save()`: services call what has to happen explicitly.

Tests: `factory_boy` factories in `apps/<app>/tests/factories.py`; every list endpoint gets a test that its number of queries stays the same for 1 and for 10 rows (pytest-django's `django_assert_num_queries` with the count measured for one row) — that is what an N+1 query breaks; a hard-coded number would break with every harmless optimisation.

## 5. API layer — Django Ninja variant

```python
# config/api.py
from django.urls import path
from ninja import NinjaAPI
from ninja.security import django_auth

from django.conf import settings

from apps.accounts.api.auth import router as auth_router
from apps.core.api.health import router as health_router

api = NinjaAPI(
    title="<Project> API",
    auth=django_auth,          # session auth; Ninja enforces CSRF for cookie auth
    csrf=True,                 # (keyword exists on older releases; drop it if the current one removed it)
    docs_url="/docs" if settings.DEBUG else None,
    urls_namespace="api",
)
api.add_router("/health", health_router)
api.add_router("/auth", auth_router)
# Mount each feature's router here, e.g. the projects router under "/projects".

urlpatterns = [path("api/", api.urls)]
```

Check the current Ninja docs for the CSRF keyword — its handling changed between releases; the requirement is that unsafe methods with session auth require the CSRF token.

```python
# apps/core/api/health.py
from ninja import Router

router = Router(tags=["health"])

@router.get("", auth=None)
def health(request):
    return {"status": "ok"}
```

The health route must resolve to exactly `/api/health` (no trailing slash, no auth) — the SSL-redirect exemption, the Docker healthcheck and the CI smoke test all use that path. For DRF: `HealthView(APIView)` with `authentication_classes = []` and `permission_classes = [AllowAny]`.

Resource routers live in `apps/<feature>/api/<resource>.py`, schemas in `apps/<feature>/schemas/<resource>.py` (`Schema`/`ModelSchema`, separate `…In`, `…Out`, `…Patch`). Use `uuid.UUID` for path params (`/{project_id}`).

OpenAPI export for the frontend client:
```bash
uv run python manage.py export_openapi_schema --api config.api.api --indent 2 --output ../frontend/openapi.json
```

## 6. API layer — DRF variant

```python
# settings.py additions
REST_FRAMEWORK = {
    "DEFAULT_AUTHENTICATION_CLASSES": ["rest_framework.authentication.SessionAuthentication"],
    "DEFAULT_PERMISSION_CLASSES": ["rest_framework.permissions.IsAuthenticated"],
    "DEFAULT_SCHEMA_CLASS": "drf_spectacular.openapi.AutoSchema",
    "DEFAULT_PAGINATION_CLASS": "rest_framework.pagination.LimitOffsetPagination",
    "PAGE_SIZE": 50,
    "DEFAULT_RENDERER_CLASSES": ["rest_framework.renderers.JSONRenderer"]
        + (["rest_framework.renderers.BrowsableAPIRenderer"] if DEBUG else []),
}
SPECTACULAR_SETTINGS = {"TITLE": "<Project> API", "SERVE_INCLUDE_SCHEMA": False, "COMPONENT_SPLIT_REQUEST": True}
```

`SessionAuthentication` enforces CSRF for authenticated unsafe requests.

```python
# config/api.py
from django.conf import settings
from django.urls import include, path
from drf_spectacular.views import SpectacularAPIView, SpectacularSwaggerView
from rest_framework.routers import DefaultRouter

from apps.accounts.api import urls as accounts_urls
from apps.core.api.health import HealthView

router = DefaultRouter(trailing_slash=False)  # API paths never end in /
# Register each feature's viewsets here, e.g. ProjectViewSet under "projects".

urlpatterns = [
    path("api/health", HealthView.as_view()),
    path("api/auth/", include(accounts_urls)),
    path("api/", include(router.urls)),
]
if settings.DEBUG:
    urlpatterns += [
        path("api/schema/", SpectacularAPIView.as_view(), name="schema"),
        path("api/docs/", SpectacularSwaggerView.as_view(url_name="schema")),
    ]
```

Viewsets in `apps/<feature>/api/<resource>.py`, serializers in `apps/<feature>/serializers/<resource>.py`. `lookup_value_converter = "uuid"` on viewsets keeps URL matching strict.

OpenAPI export: `uv run python manage.py spectacular --validate --fail-on-warn --format openapi-json --file ../frontend/openapi.json`.

## 7. Auth endpoints (session + CSRF)

Same contract for both variants, under `/api/auth/`, **without trailing slashes** (`/api/auth/login` — nginx's rate limit matches that exact path):

| Method | Path     | Auth | Purpose |
|--------|----------|------|---------|
| GET    | `csrf`   | none | `ensure_csrf_cookie` → sets `csrftoken`; SPA calls it on boot |
| POST   | `login`  | none (CSRF required) | `{username, password}` → `authenticate` + `login`, returns current user |
| POST   | `logout` | session | `logout` |
| GET    | `me`     | session | current user or 401 |

Login must still require the CSRF token even though the user is anonymous (Ninja: `@router.post("login", auth=None)` plus `django.views.decorators.csrf.csrf_protect`-equivalent check; DRF: an `APIView` with `authentication_classes = []` and `@method_decorator(csrf_protect)`). Return the user as `{id, username, email, is_staff}` — the `id` is a UUID string. Write tests for: login with wrong password → 401/400, login without CSRF token → 403, `me` after login → 200.

## 8. Tooling

All tool configuration lives in `pyproject.toml` (one source for `just`, CI and the editor):

```toml
[project]
license = "<LICENSE_ID>"   # proprietary: "LicenseRef-Proprietary"

[tool.uv]
package = false

[tool.ruff]
line-length = 110
target-version = "<py3xx matching chosen Python>"
extend-exclude = ["*/migrations/*"]

[tool.ruff.lint]
# Correctness, readability and safety — limits against tangled and deeply nested code
# (C90), deliberately none against length (no PLR0915 statements, no max-lines).
select = [
    "E", "W", "F", "I", "UP", "B", "DJ", "SIM", "C4", "RET", "PIE", "PTH", "RUF",
    "C90",  # cyclomatic complexity
    "DTZ",  # timezone-aware datetimes only
    "T20",  # no print()
    "ERA",  # no commented-out code
    "N",    # naming conventions
    "S",    # security patterns (bandit)
    "BLE",  # no blind `except Exception` that swallows errors
    "TRY",  # exception handling: no `except: pass`, re-raise with context, …
    "PERF", # slow patterns (building a list in a loop, …)
    "FURB", # older, longer spellings of what the standard library does directly
    "PT",   # pytest: tests that assert something, no stray fixtures
    "PGH",  # no blanket `# noqa` / `# type: ignore` (RUF100 reports unused ones)
]
ignore = [
    "S603", "S607",  # subprocess with fixed argument lists (pg_dump, uv) is intended
    "RUF012",        # Django's class attributes (Meta.ordering, list_display) are lists by convention
    "N806",          # `User = get_user_model()` and similar inside functions
    "TRY003",        # messages passed to the exception class are fine
]

[tool.ruff.lint.mccabe]
max-complexity = 15

[tool.ruff.lint.per-file-ignores]
"**/tests/**" = ["S101", "S105", "S106"]  # assert, passwords in fixtures
"conftest.py" = ["S101"]
"scripts/**" = ["T201"]                   # command-line tools print their result

[tool.ruff.lint.isort]
known-first-party = ["apps", "config"]

# [NINJA] Ninja declares parameters with these in defaults.
[tool.ruff.lint.flake8-bugbear]
extend-immutable-calls = ["ninja.Query", "ninja.Path", "ninja.Body", "ninja.Form", "ninja.File"]

# Layers inside every app: api may use services, selectors and models; services may use
# selectors and models; nothing imports api. core imports no other app. `lint-imports` runs in
# `just check-backend`; a test (ci.md section 3) fails when an app is missing here.
[tool.importlinter]
root_packages = ["apps", "config"]

[[tool.importlinter.contracts]]
name = "Layers inside each app"
type = "layers"
containers = ["apps.core", "apps.accounts"]
layers = ["api", "(services)", "(selectors)", "models"]

[[tool.importlinter.contracts]]
name = "core depends on no other app"
type = "forbidden"
source_modules = ["apps.core"]
forbidden_modules = ["apps.accounts"]

[tool.pytest.ini_options]
DJANGO_SETTINGS_MODULE = "config.settings_test"
python_files = ["test_*.py"]
# In parallel (pytest-xdist), each worker with its own test database; more than 8 only
# add start-up time. One process, e.g. to debug with --pdb: -n 0.
addopts = "-n auto --maxprocesses=8"
# pytest-randomly shuffles the test order on every run, so tests that pass only because of
# another test's leftovers fail; the seed is printed (`--randomly-seed=…` to repeat,
# `-p no:randomly` to switch it off while debugging).

[tool.coverage.run]
source = ["apps", "config"]
omit = ["*/migrations/*", "config/asgi.py", "config/wsgi.py", "manage.py"]

[tool.coverage.report]
fail_under = 90
skip_covered = true
show_missing = true

[tool.mypy]
plugins = ["mypy_django_plugin.main"]   # DRF: also "mypy_drf_plugin.main"
strict = true
# Checks against cases the types rule out (`if x is None` for a non-optional x, a branch
# that can't run) are reported instead of kept "to be safe".
warn_unreachable = true
strict_equality_for_none = true
enable_error_code = [
    "redundant-expr",
    "truthy-bool",          # `if obj:` on an object that is always true
    "possibly-undefined",   # a variable only set in some branches
    "ignore-without-code",  # `# type: ignore` names the error it silences
    "exhaustive-match",     # a `match` over an enum or union misses a case
]
exclude = ["/migrations/"]

[[tool.mypy.overrides]]
module = ["*.migrations.*"]
ignore_errors = true

[[tool.mypy.overrides]]
# Tests: still type-checked, but test functions and fixtures need no annotations.
module = ["apps.*.tests.*", "conftest"]
disallow_untyped_defs = false
disallow_incomplete_defs = false
disallow_untyped_calls = false

[[tool.mypy.overrides]]
# scripts/check_translations.py runs with `uv run --with polib`; polib is no dependency.
module = ["polib"]
ignore_missing_imports = true

[tool.django-stubs]
django_settings_module = "config.settings_test"

[tool.deptry]
# Tests may use dev dependencies (pytest); the CI scripts bring their own (polib).
extend_exclude = [".*/tests/", "conftest\\.py", "scripts/"]

[tool.deptry.per_rule_ignores]
# Used at runtime, never imported: DB driver (ENGINE string) and the WSGI server.
DEP002 = ["psycopg", "gunicorn"]
```

`strict = true` stays, and so do the three checks against impossible cases: delete such a check rather than silencing it — keep one only where data really comes from outside the types (a raw request body, an untyped library), with the reason in a comment. Cognitive complexity (how hard a function is to follow; nesting costs more than a flat list of cases) is limited to 15 by `complexipy` in `just check-backend`.

`strict = true` stays; a third-party package without types gets a targeted override with `ignore_missing_imports = true`, never a looser global setting. `# type: ignore[code]` only with the reason next to it. Endpoints behind auth take a request type whose `user` is the project's `User` (e.g. `AuthedRequest` in `apps/core/api/security.py`), so mypy knows `request.user`.

The tests run natively on SQLite (no database server needed) and in CI on PostgreSQL (`DB_HOST` in the job); `settings_test.py` makes them independent of the developer's `.env` otherwise. Tests that need PostgreSQL itself (a real `pg_dump`, the procrastinate queue) get `pytest.mark.skipif(connection.vendor != "postgresql", …)`; everything else must pass on both, so mock what differs (e.g. `backups.available`, `subprocess.run` for pg_dump) instead of skipping. Natively against PostgreSQL: `just db-up` and `DB_HOST=localhost`. Before the first run of the dev server, `cp .env.example .env` — do this during scaffolding so verification works.
