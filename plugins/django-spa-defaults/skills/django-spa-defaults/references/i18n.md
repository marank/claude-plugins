# Translations

The **frontend** always ships English and German (at least). The **backend** speaks German only when it has to — when users see its texts directly: emails, generated documents, messages shown as they come from the API (decided in step 1). Otherwise the backend stays English only: no `locale/`, no translation check, no gettext in the image, and the frontend translates what it shows (error codes, enum labels). Blocks marked `[BACKEND_DE]` in the assets are kept only for a German-speaking backend. Source strings are English; further languages only when step 1 asks for them (then repeat the German steps per language: `-l <lang>` in makemessages, the CI step and the task, a folder in the frontend locales, a `docs/<lang>/` tree).

## Backend (only if it speaks German)

For an English-only backend remove instead: the `[BACKEND_DE]` blocks (justfile recipes and lines, the two i18n tasks, the gettext step in CI, the AGENTS.md rule — keep its `[BACKEND_EN]` line), `gettext` from the Dockerfile's apt line and `&& python manage.py compilemessages …` after `collectstatic`, and `backend/scripts/check_translations.py`.

- Settings per `settings.md` section 5: `LANGUAGE_CODE` default = the project's main language, `LANGUAGES = [("en", "English"), ("de", "Deutsch")]`, `LOCALE_PATHS = [BASE_DIR / "locale"]`, `LocaleMiddleware` after `SessionMiddleware`.
- Source strings in English, marked with `gettext_lazy as _` in models (`verbose_name`), admin, validation errors, API error messages and email texts.
- Task **i18n: update backend messages** (`makemessages -l de --ignore=.venv`), translate every entry in `backend/locale/de/LC_MESSAGES/django.po` (no empty `msgstr`, no `fuzzy`). Commit the `.po` file; the `.mo` files are built in the Dockerfile (`compilemessages` next to `collectstatic`), in CI, and locally with **i18n: compile backend messages**.
- `backend/scripts/check_translations.py` (asset) fails on untranslated or fuzzy entries; `just check-backend` (and so CI) runs it after `makemessages`, so the scaffold's own strings (user model, auth errors) must be translated before reporting.

## Frontend

See `frontend.md` section 5: `src/i18n/locales/{en,de}/<area>.ts`, a test for equal keys, `Accept-Language` from the API client. The library (vue-i18n or react-i18next) is in the variant file.

## Docs

With `docs/`: every page in `docs/de/` and `docs/en/` under the same path (`docs.md`); the build fails on a missing counterpart.
